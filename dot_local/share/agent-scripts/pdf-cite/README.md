# PDF Cite

PDF 出典から本文を抽出し、逐語引用が実在することを検証する。標準ライブラリのみで
動くので poppler の導入は不要。

要約器（WebFetch など）に PDF を読ませた出力から逐語引用を作ると、**存在しない文が
引用の体裁で残る。** 実測で3件の捏造を確認している（研究論文のエラー文字列、規格の
例文、記法の例文）。逐語で引くなら本文を抽出して突き合わせる。

## 引用の実在を検証する

```sh
$XDG_DATA_HOME/agent-scripts/pdf-cite/bin/pdf-cite /abs/path/paper.pdf \
  --find "exact quote as you intend to cite it"
```

`--find` を付けたときは**検証コマンドとして振る舞う**。指定した語句が1つでも本文に
なければ終了コード 1 を返す。複数の `--find` をまとめて渡せる。

## 抽出できたかだけ確認する

```sh
$XDG_DATA_HOME/agent-scripts/pdf-cite/bin/pdf-cite /abs/path/paper.pdf
```

字数と冒頭 300 字を出す。`--dump` で全文。

## 知っておくこと

- **絶対パスで渡す。** サンドボックス下と非サンドボックス下で `TMPDIR` が異なる環境が
  あり、相対パスは黙って別のファイル（または存在しないパス）を指す。
- **10MB を超える PDF は WebFetch の取得上限を超える。** `curl -sL -o` で落としてから
  渡す。OMG の規格書などが該当する。
- **語間空白は PDF によって残る場合と落ちる場合がある。** LaTeX 由来の PDF はグリフ
  配置で語間を表すため空白が落ちる。このスクリプトは検索語と本文の**両側**を正規化
  するので、どちらでも一致する。片側だけ正規化すると実在する引用を「0件」と誤判定
  する（実際に起きた）。
- **画像だけの PDF からは何も取れない。** 字数が極端に少ないときは警告と診断（展開
  できた stream 数、16進文字列のみの stream 数）を stderr に出す。フォント符号化が
  必要な16進文字列には対応しない。

## 自己検証

```sh
$XDG_DATA_HOME/agent-scripts/pdf-cite/bin/pdf-cite --selftest
```

最小の PDF を組み立てて、抽出・空白差の吸収・存在しない語句の非検出・空 PDF の扱いを
検証する。抽出規則を変えたら走らせる。
