# 主眼論破

反論の力は、何を論破したかで決まる。

逐語引用を取って誤りを示すところまでで、反論としては成立する（DH5）。
そこから一段上がるのは、当てた先が対象の**主眼**であるときだけである。

些末な点を選んで正確に論破しても、DH5 の形は保たれる。
原文の主張がその点に依存していないなら、誤字、名前や数字の誤り、語調への指摘が果たすのは、書き手の信用を落とすことだけである。

主眼に当てるには、主眼が何であるかを先に明示的に確定する必要がある。
対象の文章が自分の主眼を明示していないことは多く、書き手自身が把握していないこともある。
そのため、この手順の成果物は反論だけではなく、再構成した論理構造を含む。

対象: `$ARGUMENTS`（未指定なら、どの文章を対象にするかユーザーに確認する）

## 前提

- サブエージェントを起動できること。起動できないなら、この手順を使わない。**本体セッションで構造抽出と反論を続けて書く形に置き換えてはいけない。** 反論したい側が主眼を認定すると、反論しやすい点が主眼として選ばれる。

## 1. 着手前に確認する

次の4点を確認する。
1つでも満たさないなら、サブエージェントを起動せず、ここに書いた行動に戻る。

| 確認すること | 満たさないときの行動 |
| --- | --- |
| 対象の全文が、逐語引用できる形で手元にある | 取得してから戻る。要約、抜粋、記憶による再述で代替しない |
| 反論の動機が、原文の主張が依存している命題にある | 誤字、数字、語調だけが動機なら、この手順を使わない。指摘するなら誤りの訂正として単独で行う |
| 自分の主張と対象の主張が、同じ対象について述べている | 自分の主張を一文で書き、対象と突き合わせる。すれ違いなら、成果物は反論ではなく、どこがすれ違っているかの記述になる |
| 主眼をすでに決めているなら、それを仮説として扱う | 第1段には渡さない。渡すと、その点を主眼と認定する方向に読まれる |

**この4点はユーザーに確認する。** 本体セッションが推測で埋めると、埋めた内容がそのまま第1段の前提になる。

## 2. 第1段: 論理構造の再構成

サブエージェントに渡すのは下のプロンプトと対象だけ。
**なぜこの依頼が来たか、ユーザーがどこに反論したいか、ユーザー自身の立場は渡さない。**

```
あなたは文章の論理構造を再構成します。この依頼の経緯や、読み手がどこに反論したい
かは与えられません。

対象: <ファイルの絶対パスまたは本文>

## やること

1. 文章を先頭から読み、事実の記述と主張を区別し、主張だけを出現順に番号を付けて
   列挙する。
2. 各主張について次の表を埋める。

   | 番号 | 主張 | 逐語引用と位置 | 依存する主張 | 分類 |

   - 主張: 一文で書く。原文の語を使う。
   - 逐語引用と位置: 原文からの逐語引用と、行番号、節見出し、段落番号のいずれか。
     引用が取れない主張は「引用なし」と書く。
   - 依存する主張: 他の主張の番号。依存関係が原文に書かれていないなら「明示なし
     (推測)」と書き、推測した接続を一文添える。
   - 分類: 主眼候補 / 主眼を支える命題 / 些末。
3. 主眼候補を挙げ、それぞれについて主眼候補と判定した理由を、依存関係の向きで
   説明する(他の主張がそれを支えているか、それが落ちると残りの主張が目的を失うか)。
   主眼候補は複数あってよい。1つに絞らない。
4. 構造が壊れている箇所を報告する。次を含む。

   - 同じ語が別の意味で使われている
   - 結論が、挙げられた根拠のどれからも出てこない
   - 使われている前提が書かれていない
   - 同じ主張が別の言い方で複数回現れ、どれが正式な形か決まらない

5. 章立てや接続表現が示す構造と、依存関係が示す構造が食い違うときは、両方を書き、
   食い違いを指摘する。書き手が自分の構造を把握していない前提で読む。

## 守ること

- 扱うのは書かれた主張だけである。書き手の属性、立場、動機、語調は評価に入れない。
- 構造を整えるために主張を補うときは「推測」と明記する。原文の語で書ける範囲を
  超えた要約をしない。
- 各主張が正しいかは判定しない。構造の再構成だけを行う。
- ファイルを変更しない。報告のみ。
- 追加の質問はせず、1回で完了する。
```

## 3. 主眼を確定する

第1段の報告を受け、本体セッションがユーザーに次を示す。

- 主眼候補と、それぞれの根拠となる逐語引用
- 引用が取れなかった主張
- 「推測」と印された接続

**主眼を1つに確定するのはユーザーである。** 主眼が何であるかへの明示的な commit は、あとで対象の書き手や読者から問われる側のものであり、本体セッションが代わりに負えない。

主眼が複数あるときも、確定するのは1つでよい。
論破が成立する必要があるのは主眼のうち少なくとも1つである。

第1段の候補とユーザーの見立てが食い違うときは、食い違いをそのまま示す。
どちらかに寄せて丸めない。

## 4. 第2段: 反論の起草

確定した主眼、第1段の表、対象、ユーザーの見立て（あれば）を渡す。

```
あなたは、与えられた主眼に対する反論を起草します。

対象: <ファイルの絶対パスまたは本文>
主眼: <確定した主眼を一文で>
構造: <第1段の表>
読み手の見立て: <あれば一文で。無ければ「なし」>

見立ては仮説である。原文と照らして支持できないなら、支持できないと報告する。
見立てが成立する方向に原文を読まない。

## やること

1. 反論を当てる先を1つ選ぶ。選べるのは次の2つだけ。

   - 主眼そのもの
   - 主眼が依存している命題(構造の表の依存関係でたどれるもの)

   選んだ先が崩れたときに主眼がどうなるかを一文で書く。
2. 当てる先の逐語引用を原文から取る。引用が取れないなら、反論を書かずに「引用が
   取れない」と報告して終わる。
3. 反論を次の形で書く。

   対象の主眼は〈x〉であるように見える。根拠となる記述は次のとおり。

   > 〈逐語引用〉

   これは次の理由で成り立たない。〈理由〉

4. 書いた反論を自分で点検し、結果を報告に含める。

   - 理由が、引用した命題そのものに当たっているか。似た別の命題に当たっていないか
   - 引用のあとの本文が、反対の立場の言い直しや書き手への評価に落ちていないか
   - 根拠にしているのが、原文の主張が実際に依存している命題か
   - この反論が成立しても主眼が残るか。残るなら些末な点への反論であり、そう報告する

5. 反論が成立しないと判断したときは、成立しないと報告する。次のどれかを明示する。

   - 原文の主張が正しい
   - 不同意が実在せず、双方が別のことを論じている(何と何がすれ違っているかを書く)
   - 判断に足る記述が原文にない

## 守ること

- 主眼と違う的に当てるなら、そうしていることを反論の文中に書く。
- 反論の材料は原文の記述だけである。書き手の属性、権威の有無、語調は材料にしない。
- この手順は反論が正しいことを保証しない。形が整ったことと正しいことを分けて報告する。
- ファイルを変更しない。報告のみ。
- 追加の質問はせず、1回で完了する。
```

## 5. 統合して出力する

統合は本体セッションが行う。

第2段の点検結果を1件ずつ採用するか却下するかを決め、**却下したものには理由を持つ**。

成果物には次の4つを必ず含める。

1. **論理構造**：主張、逐語引用、依存関係、主眼と些末の分離。原文に書かれていた接続と、再構成で補った接続を区別して示す。
2. **確定した主眼**：一文と、根拠となる逐語引用。
3. **反論**：または反論が成立しない理由。
4. **この成果物が保証しないこと**：形が DH6 であっても内容は誤りうる。

1 を落とさない。
対象の書き手が自分の構造を把握していない場合、書き手にとって最も使える部分は 1 である。
反論が成立しなかったときも 1 は残して渡す。

公開する反論として使うなら、公開前に書き手個人への評価が混ざっていないかを見る。
言い方がきつくなっているときは、多くの場合その部分に反論の中身がない。

## 守る制約

- **第1段に、どこに反論したいかを渡さない。** 渡すと、反論しやすい点が主眼として返ってくる。渡さないおかげで、同じ手順が自分の文章にも他人の文章にも使える。
- **主眼への commit を省略しない。** 「全体として間違っている」で止めると、何を論破したかが定まらず、成立の判定もできない。
- **逐語引用が取れないまま進めない。** 引用が取れないときに反論の相手になっているのは、原文ではなく再構成した像である。
- **形の上限と内容の正しさを分けて報告する。** この階層が与えるのは説得力の上限だけである。DH2 以下は常に説得力を持たないが、DH6 の形をとった反論が正しいとは限らない。
- **各段は1回。** 反論を通すために段を回し直す形にしない。成立しないという第2段の報告は、そのまま成果物になる。
- **対象の文章を書き換えない。** この手順が作るのは構造と反論の文書だけである。
- **サブエージェントに割り当てる能力を落とさない。** 散文からの構造抽出は能力差が出る。モデルを明示指定せず、セッションのものを継承させる。

## 変えてよいところ

原文に根拠があり、動かさないもの。

- 主眼が何であるかを明示的に確定すること
- 逐語引用を取ること、取れないときに藁人形を疑うこと
- 引用の対象は主眼そのものでなくてよく、主眼が依存する命題でよいこと
- 些末な点への反論を主眼への反論と数えないこと
- 的をずらすときに、ずらしたことを明示すること
- 引用を置いたあとの本文が下位の形に落ちていないかを点検すること
- 形が整っても正しさは保証されないこと

この手順が足したもので、根拠を持たないもの。合わなければ変える。

- 段を2つに割り、第1段に反論の意図を渡さないこと
- 構造を表で出すこと、および列の構成
- 主眼の確定をユーザーに戻すこと
- 着手前の4つの確認
- 主眼候補を1つに絞らせずに返させること

## 出典

Paul Graham, "How to Disagree" (March 2008). <https://paulgraham.com/disagree.html>

DH0 から DH6 の定義、DH5 における引用の要件、些末な点への反論の扱い、階層が勝敗を決めず説得力の上限しか与えないことは、この一次資料に基づく。
