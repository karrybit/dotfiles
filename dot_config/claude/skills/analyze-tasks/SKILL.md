# 並行実行可能なタスクへの分解

入力: `$ARGUMENTS`。未指定なら、対象のファイルか Issue
番号をユーザーに確認する。

この手順は、同時に着手しても互いを壊さないタスクの集合を作る。
分解は「独立しているか」で判定し、「小さいか」では判定しない。
優先順位を付けることは目的にしない。

## 作業全体にかかる規則

- 同じファイルを触る2タスクは、独立していない証拠として扱い、
  依存を書き足すのでなく、分解し直すか直列化する。
- 3つの尺度は行動の引き金として使い、「3つの尺度」の表にない軸を足さない。理由:
  引き金を引けない尺度は判断を薄める。
- 出力には `生成元` を記録する。理由: この markdown は Issue
  と元メモから導出した派生物で、唯一の真実の源ではない。
- 未構造の入力ファイルは、書き換えず、消さず、移さない。理由:
  元メモは3軸の判定とローカル分割の切り方を後から検算する唯一の材料で、
  gitignore された場所にあれば git 履歴からも復元できない。
- 認証情報・トークン・秘密値・セッション状態は、Issue
  本文や元メモに書かれていても持ち込まない。
  「1つも捨てない」は記述の忠実性の原則で、これらを写す理由にならない。
- 進行状態・ブランチ名・PR 番号・worktree のパス・並行可能集合は、
  ファイルに書かず、「進行状態の導出」の表のとおり git と GitHub から導出する。
- この手順では worktree を作らず、コードも変更しない。実行は `parallel-work`
  が引き取る。

## 手順

1. 「入力の取り込み」に従って、入力をスキーマへ移す。
   完了条件: 入力に書かれた情報が、
   秘密値を除いてすべて出力スキーマのどこかの節にある。
2. 「3つの尺度」に従って、各タスクに影響度・作業量・重要度を付け、作業量 L
   のタスクを子タスクへ割る。
   完了条件: 作業量 L のまま残るタスクがなく、影響度 L のタスクに
   `gh search code` の結果が書いてある。
3. 「依存とファイル衝突」に従って、依存の種類を判定し、
   並行可能集合を波として求める。
   完了条件: 同時進行するタスクの組に、
   回避策の書かれていないファイル衝突がない。
4. 「出力」に従って、置き場が無視されていることを確かめてから、タスク表を書く。
   完了条件: `git check-ignore -v` が終了コード 0 を返したパスに、
   タスク表が書いてある。
5. 「合意」に従って、タスク表と並行可能集合をユーザーに提示し、合意を取る。
   完了条件: ユーザーが重要度を決め、分解に合意したことが会話に残っている。

## 入力の取り込み

| 入力 | すること |
| --- | --- |
| 既存の未構造メモ | 全文を読み、書かれている情報を1つも捨てずにスキーマへ移す |
| Issue 番号群 | `gh issue view <n>` で本文とコメントを読み、変更対象を列挙する |
| 出力先に既存ファイルがある | 読んでから更新する。新規作成で上書きしない |

未構造メモから移すときは、落としやすい次の4種を拾う。移し先は、
出力スキーマの同名の節にある。

- リポジトリ固有の運用ルール（CI の確認方法、既知の lint 制約、
  サンドボックスの制約）
- ファイル衝突のホットスポット
- 未 Issue 化の検討事項
- 親 / トラッキング Issue と、その子の対応

行き場のない情報が出たら、捨てずにスキーマに節を足す。

## 3つの尺度

| 軸 | 値 | 判定基準 | 引き起こす行動 |
| --- | --- | --- | --- |
| 影響度 | S | 単一ファイル / 単一コンポーネント内 | — |
| | M | 1コンポーネント内。呼び出し側の変更は不要 | — |
| | L | 公開インタフェース（入力、名前、パス、データ形式）が変わる、または外部リポジトリからの呼び出しに影響する | `gh search code` で外部の呼び出し箇所を確認する。削除や改名を含む場合は、着手直前に取り直す（検索はインデックスベースで遅延がある） |
| 作業量 | S | 1PR で完結する | — |
| | M | 1〜2PR。1タスクとして許容する | — |
| | L | 3PR 以上 | ローカル分割する。子タスクへ割るまで着手可能にしない |
| 重要度 | 高 / 中 / 低 | 他タスクを解錠するか、ロードマップ本線か、外部の返答待ちが挟まるか | 根拠付きで提案し、ユーザーが決める。エージェントは確定させない |

- 作業量 L のまま残っているタスクは、この手順の失敗として扱い、
  子タスクへ割ってから次へ進む。
- 件数で S/M/L が変わるときは、内訳を実測してから判定する。理由: Issue
  本文の「N 箇所」は grep の生の数で、実際に手を入れる箇所と桁が違うことがあり、
  生の数で L と判定すると不要なローカル分割を作る。

## 依存とファイル衝突

次の3種を区別する。混ぜると直列化しすぎて、並行の余地が消える。

| 種類 | 判定 | 扱い |
| --- | --- | --- |
| 順序依存 | B は A がマージされないと成立しない | 直列鎖に置く。依存は B 側にだけ書く |
| ファイル衝突 | A と B が同じファイルを触る | 独立していない証拠として、分解し直す、直列化する、または「表の1行追加に留める」等の回避策を明記した上で同時進行を許す |
| 意味依存 | 同じ設計判断を2箇所で決めることになる | 片方に寄せる。判断だけの独立タスクは作らない |

- 回避策付きの同時進行は、衝突が機械的に解決できると言える場合に限って許し、
  言えないなら直列化する。
- 並行可能集合は波として示す。第1波は依存を持たないタスク全部、
  第2波はその完了で解錠されるタスクで、人数や担当を前提にしない。
- 波はファイルに書かず、聞かれた時点で依存欄と現在の PR
  状態から計算して会話で示す。理由: 何かがマージされるたびに書き換えが要る。

## 出力

- 置き場は、メインの作業ツリー（`git worktree list` の先頭）のルート直下の
  `.analyze-tasks/backlog.md` に固定し、リポジトリごとに名前を変えない。理由:
  次のセッションが探索なしで見つけ、再実行が新規作成でなく更新になる。
- worktree から実行しているときも、置き場をメインの作業ツリーに保つ。理由:
  worktree 側に書くと、その worktree が消えたときに失われ、
  メインとの二重の真実の源になる。
- ディレクトリ名のドットを保つ。理由: 非ドットのルートディレクトリは chezmoi
  のソースツリーでソースエントリとして扱われ、`chezmoi apply` で `$HOME`
  に配備される。ドット接頭辞はツール所有の状態を表す慣習（`.git` / `.claude` /
  `.venv`）でもあり、リポジトリの内容と衝突しない。
- 書き込む前に、`git check-ignore -v .analyze-tasks/backlog.md`
  で無視されていることを確かめる。一致した無視規則を表示して終了コード 0
  なら書き、1 なら書き込まない。
- 既定では global の `~/.config/git/ignore` の `/.analyze-tasks/`
  が一致するので、リポジトリ側の `.gitignore` には手を入れない。
- 一致しない環境（global ignore が未配備など）では、
  `${XDG_STATE_HOME:-$HOME/.local/state}/agents/analyze-tasks/<repo>/backlog.md`
  に退避する。
- メインの作業ツリーのルートが sandbox
  の書き込み許可外のとき（許可されるのは作業中 worktree の `.`
  だけのことがある）は、`git check-ignore` が通ったあと、
  書き込みだけサンドボックス外実行の承認を取る。
- このファイルを commit される場所に置かない。理由: この確認は安全境界のためで、
  ファイルには Issue から写した内部の名前や URL が入る。
- タスク ID には Issue 番号をそのまま使う（`#46`）。1つの Issue
  をローカルで分割した子には連番を足し（`#44-1` / `#44-2`）、Issue
  が存在しない作業にだけ `T1` / `T1-1` を使う。理由: ID が Issue を指すので、
  ブランチ名と worktree 名からどの Issue の作業かを直接辿れる。
- ID とは別に Issue を指したいとき（他タスクの完了で解消される Issue
  など）だけ、`関連:` を足す。
- 並行数の上限はこのファイルに書かない。理由:
  上限は人間のレビュー体力という実行側の制約で、
  3軸評価や依存分析からは導出できない。`parallel-work`
  が着手前にユーザーと合意し、ヘッダーの `生成元` 行の直後に追記する。

出力スキーマ:

````markdown
# <タイトル>

- 生成元: <元ファイルのパス / Issue 番号の列>

## タスク

- [ ] **#46** deploy-status 通知 action を追加する · 影響:S 作業:S 重要:高 · 依存:なし
  - 対象: `actions/notify/deploy-status/**`
  - 検証: `gh pr checks`（actionlint / ghalint / zizmor / pinact）
- [ ] **#44** build-n-push workflow と部品 action を追加する
  · 影響:L 作業:L 重要:高 · 依存:なし
  - 作業量 L のため子タスクへ分割。#44 自体は着手しない
  - [ ] **#44-1** Secrets Manager 取得 action · 影響:S 作業:S · 依存:なし
    - 対象: `actions/secrets/aws/**`
  - [ ] **#44-2** workflow を合成する · 影響:L 作業:M · 依存:#44-1
    - 関連: #37（この完了で解消する）
    - 影響 L: `gh search code` で外部呼び出しを確認済み（0件、2026-08-16 時点）
- [ ] **T1** lint の既存指摘を棚卸しする（Issue 未作成）
  · 影響:S 作業:M 重要:低 · 依存:なし

## ファイル衝突ホットスポット

| ファイル | 触るタスク | 回避策 |
| --- | --- | --- |
| `README.md` | #46, #40, #48 | 1行追加に留めれば機械的に解決でき、同時進行可 |
| `CONTRIBUTING.md` | #39 のみ | 衝突なし |

## 親 / トラッキング Issue

単独の PR を持たず、子が終わったら閉じる Issue。タスク表には並べない。

| Issue | 追跡対象 | 閉じる条件 |
| --- | --- | --- |
| #34 | #46, #44, #48 | 全部マージ |
| #37 | #44-2 | #44-2 のマージで解消。不採用なら最小対応が別途必要 |

## 対象外・保留

- <スコープ外と判断したものと、その理由>

## 未 Issue 化の検討事項

- <まだ Issue になっていないが記録しておくもの。着手するなら T 番号でタスク表へ>

## このリポジトリ固有の運用ルール

- <元メモから引き継ぐ。捨てない>
````

## 進行状態の導出

保存するのは判断と分析の結果だけにする。次のものは git と GitHub から導出する。
理由: ファイルに持つと変更のたびに書き換えが要り、二重の真実の源になってずれる。

| 知りたいこと | 導出方法 |
| --- | --- |
| いま進行中のタスク | `git worktree list`（ディレクトリ名が ID） |
| ブランチ名 | 規約から導く。ID の `#` を外したものが接頭辞 |
| PR 番号と draft / merged | `gh pr list --state all --json number,headRefName,isDraft,state` |
| 並行可能集合 | 依存欄と上の PR 状態から計算する。波は書き留めない |
| このファイル自体が陳腐化しているか | `gh issue list --state all --json number,state` と表の ID を突き合わせる。表に無い open Issue、または未チェックなのに closed の Issue があれば作り直す |

- 鮮度は最後の行で判定し、ファイルに更新日を持たせない。理由:
  知りたいのは経過時間ではなく導出元が変わったかで、
  突き合わせのほうが日付より正確で、保存もいらない。
- チェックボックスだけはファイルに残す。理由:
  1タスクにつき変わるのはマージ時の1回だけで、
  コマンドを打たずに全体を見渡せる価値が書き換えのコストを上回る。
- 状態を聞かれたら、ファイルを読まずに上のコマンドを実行する。ファイルと git
  がずれていたら、git を正とする。

## 合意

分解の誤りは実行に入ってからでは巻き戻しが高いので、
最初の編集より前に合意を取る。

- 重要度はユーザーが決め、提案のまま確定させない。
- 新規の GitHub Issue を作る場合だけ、
  既存ルールどおりタイトルと境界を先に確認する。ローカル分割だけなら Issue
  は作らない。
