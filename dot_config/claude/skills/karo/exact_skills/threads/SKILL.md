# 会話の記録（threads）

- 会話は話題で分ける。1 つの話題は `~/cos/threads/` の 1 つのファイルで、その話題で進めるタスクは 0 個以上ある。
- 書き込みは record の指示で行う（`karo:record` skill）。下の `<scripts>` は `~/.config/claude/skills/karo/scripts` で、この `~/` の形のまま書く。

## 書き方

- 書き方は `~/cos/threads/template.md` に従う。
- ファイル名は、タスクで始めた話題は `<タスクID>-<話題>.md`、議論だけで始めた話題は `YYYY-MM-DD-<話題>.md`（作った日）にする。`<話題>` は、ブランチ名の title と同じく英語の kebab-case にする（thread-show は、パスに ASCII 以外の文字があるファイルを開かない）。
- 話題はフロントマターの `topic` に短く書き、タスク ID は入れない（1 つの話題を複数のタスクで進めることがあるので、タスクはフロントマターの `tasks` に書く）。フロントマターの埋め方は `karo:frontmatter` skill の種類の表の `Thread` の行にある。
- 本文は発言の見出しから始める。発言ごとに `### オーナー · YYYY-MM-DD HH:MM` か `### CoS · YYYY-MM-DD HH:MM` の見出しを置き、空行のあとに本文を書く。
- 発言と発言の間には、空行で挟んだ `***` の行を置く（`---` は直前の行を見出しに変えることがあるので使わない）。
- 本文の段落の間とリストの前には空行を入れる（ないと 2 以降の番号がリストにならない）。
- オーナーの発言は要旨を 1〜3 行で書き、CoS の発言は返事の本文を書く。
- 見出しの日付と時刻は `{日付} {時刻}` と書く。埋まる時刻は `karo:record` skill の「書き込みの指示の形」にある。

## 印

- 決まったことは、発言の中に `- 決定: <決まったこと>` の行で書く。
- 保留したことと論点は、`- 未決: <論点>` の行で書き、オーナーの判断を待つものには decision の bead の ID を添える。
- タスクのある話題の決定は、`- 決定:` の行に加えて、Beads の `決定:` の comment か decision の bead に書く（`karo:beads` skill の「判断待ちと決定」）。
- 議論だけの話題の決定は、複数のタスクかプロジェクトに効くものだけを decision の bead にし、ほかは `- 決定:` の行だけにする。

## 話題の分け方

1. オーナーの発言の中のタスク ID・URL・チケットの番号が、話題の一覧（下の「話題に戻る」）の `tasks` か `topic` に当たれば、その話題にする。CoS の直前の問いへの返事なら、その問いを書いた話題にする。
   完了条件: 話題が 1 つに決まったか、当たる話題がない。
2. 1 で決まらず、直前の続きでもないときは、発言の中の名詞 2〜3 個で `rg -l -i -e '<語>' -e '<語>' threads` を `~/cos` で 1 回だけ実行し、候補を 5 つまでに絞る。
   完了条件: 候補の一覧（空でもよい）が手元にある。
3. 続き・候補の話題への復帰・新しい話題・複数の話題のどれかを選ぶ。決まらなければ新しい話題に書く（既存の話題に混ぜると、その話題の記録が混ざる）。候補が 1 つあってあと一歩のときだけ、返事の末尾に「<話題> の続きなら言ってください」と添える。
   完了条件: 発言ごとに、書くファイル（新しい話題なら作るファイル名）が決まっている。

- 1 つの返事が複数の話題にまたがるときは、話題ごとに分けて、それぞれのファイルへの追記を指示に入れる。
- 返事の末尾に別の話題の問いを添えたときは、その問いをその話題のファイルに書き、オーナーの答えもそこに書く。
- ファイルには、その話題のことだけを書く。
- 話題の中で仕事を頼まれたら、Beads にタスクを作り、その ID をフロントマターの `tasks` に足す（ファイル名は変えない）。分けたタスクの会話を書いたときも、その ID を `tasks` に足す。
- 書き込みの指示では、threads の項目ごとに、その発言のタスクを `タスク:` の行で宣言する（タスクのない話題は `なし`。書き方は `karo:record` skill の「書き込みの指示の形」）。`threads/memo.md` への項目には置かない。
- 宣言のタスクがファイルの `tasks` にないと record が NG にするので、発言をそのタスクの話題のファイルに書き直す。その話題のファイルがなければ、`新規:` でフロントマターから書く。`tasks` に ID を足して通すのは、その話題で頼まれた仕事のタスクか、そのファイルのタスクから分けたタスクのときだけにする。

## 話題を直す

- 発言の見出しの日時と本文は変えずに動かす（journal の出典と `derived_from` が見出しの日時を指す）。
- 移す（誤った話題に書いた発言）: 1 つの指示に、元のファイルからそのブロックを消す `置き換え`（新しい本文を空にする）と、移し先に同じ本文を足す `追記` を入れる。
- 分割: 新しい話題のファイルを `新規:` で作り、そこへ上の「移す」で移す。移したことは `commit 本文:` に書き、元のファイルにメモを残さない。
- 統合: 片方のブロックをもう一方へ「移す」で移す。空になったファイルは、フロントマターに `status: deprecated` を足して残す（record にファイルを消す項目はない）。日時が前後するブロックが入ってよい。
- 名前を変える: フロントマターの `topic` と `description` を `置き換え` で直し、ファイル名は変えない（過去の `derived_from` と journal の出典を壊さないため）。

## 話題に戻る

- 話題の一覧は、SessionStart の hook の出力の `## threads: 最近の話題` にある（最近 14 日の 15 件）。足りなければ `<scripts>/thread-index` を単独で実行する（`--since <n>d`・`--limit <n>`・`--task <タスクID>` で絞る）。列は、ファイル名、最後の発言の日時、`topic`、`tasks`、`- 決定:` と `- 未決:` の数。
- タスクから話題を引くときは、`<scripts>/thread-index --task <タスクID>` を使う（議論だけで始めた話題は、ファイル名にタスク ID がない）。

1. 戻る話題のファイルに `rg -n '^(### |- (決定|未決):)' threads/<ファイル>` を実行し、続けて `tail -n 30 threads/<ファイル>` で直近の発言を読む（印の行は発言の一部なので、印だけで状況を決めない）。
   完了条件: 直近の議論、決定、未決が手元にある。
2. 決定が複数のタスクに効くときは decision の bead を、関わるタスクの状態は `bd show <タスクID> --json --include-comments` を読む。
   完了条件: 話題の決定と関わるタスクの今の状態が手元にある。

- 会話の全文は読み込まず、要る話題の要る範囲だけを読む。
