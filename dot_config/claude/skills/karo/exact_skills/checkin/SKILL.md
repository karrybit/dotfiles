# Checkin

- この skill は、`$KARO_HOME` の記録、Beads（`bd`）、Herdr から材料を集め、報告し、記録に残す手順を持つ。外の情報源（タスクの管理、チャット、予定表など）の取り方は、`$KARO_HOME/rule/checkin.md` の「外の情報源」の節にある。
- `bd` は、`karo:tasks` skill の「呼び方」に従って実行する。

## 手順

1. 報告の材料を集める。
   - 前回の Standup: `$KARO_HOME/standup/` の `YYYY-MM-DD.md` の最新ファイルの日付を基準にする。
   - そのファイルに `karo:checkout` skill が残した `### 明日やること` の候補。今日の推奨アクションの候補にする。
   - その日付以降の `$KARO_HOME` の `git log --since='<その日付> 00:00'` の件名と本文。
   - `karo:tasks` skill の「今の状況を読む」の表の、「ある日から動いたタスク」（その日付から）、「開いているタスク」、「判断待ち」、「7 日以上動いていないタスク」と、その節の Agent とタスクの突き合わせ。
   - 外の情報源: `$KARO_HOME/rule/checkin.md` の「外の情報源」の節にある源ごとに、節に書かれた取り方で取る。ファイルか節がなければ、外の情報源は使わない。

   完了条件: 表の 4 つの行の出力と、突き合わせの完了条件を満たした結果が手元にある。「外の情報源」の節の源のそれぞれについて、結果か「取得できなかった」が手元にある（節がなければ、外の情報源を使わなかったことが手元にある）。
2. 下の「報告の項目」を、前回からの変化とオーナーが対応すべきことを先にして、短く報告する。各項目にはタスク ID を付ける。
   完了条件: 5 つの項目がすべて報告にある。
3. オーナーがその場で決めたことは、karo 自身の長い目の運用・設計の方針なら `karo:record` skill の「Decision Record を書く」で記録にし、それ以外は `karo:tasks` skill の「判断待ちと決定」のとおり `bd` に書く。必要なら `karo:delegate` skill で Agent に指示する。
   完了条件: オーナーが決めたことごとに、`decisions/` に Decision Record を書いたか、`bd show <決定> --json` の close_reason に決定の文があるか、そのタスクに `決定:` の comment がある。
4. 報告内容と決まったことを `$KARO_HOME/standup/YYYY-MM-DD.md` に追記し（ファイルがなければ `karo:record` skill の「書く」のとおりフロントマターから作る）、本文に Checkin の記録であることを書いて、3 で書いた Decision Record と一緒に commit する（`karo:record` skill）。今日の焦点か次の行動が変わったら、`karo:record` skill の「state.md を書く」のとおり `state.md` も直す。
   完了条件: commit が `OK` の行を出した。焦点か次の行動が変わったときは、`state.md` の `更新:` が今日の日付になっている。

## 報告の項目

この順に並べる。外の情報源の結果は、`rule/checkin.md` の「外の情報源」の節がその源ごとに決めた項目に入れ、取得できなかった源は、その項目に「取得できなかった」と書く。

- 前回からの主な進捗
- 動いている Agent と担当作業（Herdr の状態をそのまま書く）
- 完了した成果物とレビュー待ち
- ブロッカーとオーナーの判断が必要なこと（選択肢と推奨を添える）。7 日以上動いていないタスクは「要確認」としてここに入れる
- 今日の推奨アクション
