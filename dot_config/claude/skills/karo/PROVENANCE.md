- notes: `~/cos` の記録のリポジトリ（`tasks/`・`threads/`・journal・record）の構造を知る plugin。manifest の `defaultEnabled: false` により、使うプロジェクトの settings の `enabledPlugins` で `"karo@skills-dir": true` にしたときだけ読み込まれる。skill（`checkin`・`checkout`・`delegate`・`goal`・`review`・`land`・`insights`・`explain`・`setup`）は `skills/` に、それぞれの `PROVENANCE.md` と一緒に置き、karrybit の skill と subagent（`herdr-agent`・`goal`・`explain`・`publish-check` など）を cos の構造と組み合わせる。サブエージェント `researcher`（`karo:researcher`）は `agents/` に置く。skill の手順が読むオーナーの値は、`<cos>/rules/<skill>.md`（`checkin.md`・`checkout.md`・`review.md`）と `<cos>/projects/<name>.md` の `## Agent の作業場所と取り込み` の節にあり、どの手順もファイルがないときの既定を持つ。複数の skill と settings の hook が使う script（`record`・`karo-check`・`thread-show`・`right-pane`・`call-check`・`settings-test`）は plugin 直下の `scripts/` に、1 つの skill だけが使う script はその skill の `scripts/`（`land`・`insights`）に置き、test は script の隣に置く。オーナーごとの値は karo に書かず、引数、`<cos>/rules/karo.yaml`（`panes:` を `right-pane` が、`uncounted:` を `insights` が `yq` で読む）、script がすでに受ける `COS_*` の env で受け取る。`land` は env と `rules/karo.yaml` のどちらでもフォルダを動かさない（理由は `land` の冒頭）。`karo-check` は `<cos>/rules/frontmatter-schema.yaml` を schema にして karrybit の `okf-lint` を呼び、そのあとに cos の構造に固有の検査を行う。`record` は、書いたものを隣の `karo-check` で確かめてから commit する。`record-test` と `karo-check-test` は、`<cos>` の schema などを読むだけで、試験の記録は一時フォルダに作る。scripts は呼び出し側の settings で許可し sandbox から除外して使うので、この plugin を配る場所の `~` の形（`~/.config/claude/skills/karo/scripts/<名前>`）で呼び、規則もその形で書く。`scripts/settings-test` に settings.json を渡すと、その規則と hook がそろっているかを確かめる。
