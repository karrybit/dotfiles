# HTML の解説の依頼の型

`SKILL.md` の 2 で、下の型の `<…>` を埋めて 1 つの依頼にする。

- 型の外の文（作り方の好み、前の版の感想）は依頼に足さない。足すと、作り手が型より依頼の言葉に合わせる。

<template>
# <元の資料の名前> の解説を、1 ファイルの HTML で作る

次の依頼を順に行う。前の依頼の完了条件を満たしてから次へ進む。

1. 情報整理: 下の「情報整理の依頼」に従い、説明の文書を `<説明の文書の絶対パス>` に作る。
   完了条件: 情報整理の依頼の手順 6 の完了条件を満たす。
2. HTML 化: 下の「HTML 化の依頼」に従い、1 の説明の文書から `<HTML の絶対パス>` を作る。
   完了条件: HTML 化の依頼の手順 3 の完了条件を満たす。
3. 控えのファイル: `<控えのファイルの絶対パス>` を、<控えのファイルの書き方の規則と、入れる値> に従って書く。
   完了条件: 控えのファイルがあり、`<控えのファイルの検査のコマンド>` の指摘が 0 件になった。

書いてよいのは、2 つの依頼が書いてよいとする場所と控えのファイルだけ。2 つの依頼の「制約」が読まないとする rubric.md は、どちらの依頼のあいだも読まない。報告は、2 つの依頼の「報告」の項目と、控えのファイルのパス。

</template>
