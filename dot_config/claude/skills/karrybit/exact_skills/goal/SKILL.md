# goal の完了の条件を書く

- goal は、完了の条件を満たすまで、作業する側が自律でターンを続ける作業。
- Claude Code の `/goal` は、ターンごとに評価役のモデルが完了の条件を判断する。評価役はツールを使わず、会話に出た内容だけで判断する（https://code.claude.com/docs/en/goal.md）。そのため、完了の条件は、作業する側の出力で満たしたかを示せる文にする。
- この skill が受け持つのは、依頼を goal に分けて、goal ごとに完了の条件を書くところまで。書いた条件で `/goal` を動かすのは呼び出し側。

## 手順

1. 依頼を goal に分ける。1 つの依頼に goal が複数あれば、goal ごとに分ける。
   完了条件: どの goal も、何を作るかと完了の条件が 1 つずつ対応している。
2. goal ごとに完了の条件を確かめる。条件は、作業する側の出力（テストの結果、コマンドの終了コード、`git status`）で満たしたかを示せる 1 行の文にする。条件が書かれていない goal、出力で示せない goal は、その goal を止めて依頼者に確かめる（ほかの goal は進めてよい）。
   - 条件は、検査できる述語（コマンドと期待する出力）と試行の上限の組にする（例: 「`bin/foo-test` が `0 failure(s)` を出すか、試行が 5 周に達した」）。所要時間は条件にしない。
   - goal ごとに、作業する側への指示に添える行き詰まりの扱いを書く: 進みが止まっても条件を緩めず、方針を変えて続ける。本当の行き詰まりか上限に達したときだけ、試したことと原因の仮説を書き残して止まる。

   完了条件: 止めなかった goal のすべてに、述語と試行の上限を 1 行に含み `/goal <完了の条件>` にそのまま渡せる完了の条件と、行き詰まりの扱いがある。止めた goal のすべてに、依頼者に確かめることがある。
3. goal ごとに、何を作るかと完了の条件と行き詰まりの扱いを、止めた goal は依頼者に確かめることを、呼び出し側に返す。
   完了条件: 返事に、1 の goal のすべてが、完了の条件か依頼者に確かめることのどちらかと一緒にある。
