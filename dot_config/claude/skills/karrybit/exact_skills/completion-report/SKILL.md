# 完了報告を書く

- 完了報告は、任された作業の最後のメッセージに書く。読むのは、自分を作ったセッション（委任した側）。
- 受け取る側は、見出しの語で項目がそろっているかを確かめる。そのため、見出しは下のひな形の語と順のまま書く。

## 書き方

- 最後のメッセージに、ひな形の 7 つの見出しを、すべて、この順に書く。
- 中身のない見出しは、消さずに、本文を「なし」の 1 語にする。「なし」は、当てはまるものがないことを表す。確かめていないことは「なし」にせず、「確かめられなかったこと」に書く。
- 「実行した確かめ」には、実行したコマンドと、その出力の要点（テストの件数、終了コード、`git status` など）を書く。
- 「確かめられなかったこと」には、確かめられなかったことと、その理由を書く。
- 「新しく作ったもの」には、作ったものごとに、探した既存のツール（公開の plugin や skill を含む）と、それを使わなかった理由を書く。
- 「simple & easy より複雑にしたところ」には、考えた中でいちばん simple & easy な案より複雑にしたところと、それを求める本質的な複雑さを書く。
- 「扱わないコーナーケース」には、検討したうえで扱わないことにしたコーナーケースと、扱わない理由を書く。
- 依頼が報告に足した項目は、7 つの見出しの中身と重なっても、7 つの見出しの後ろに、依頼の語をそのまま `## ` の見出しにして書く。

<template>
## 変更の要約

## commit と PR
commit の hash。PR を作ったときは、その URL も。

## 実行した確かめ

## 確かめられなかったこと

## 新しく作ったもの

## simple & easy より複雑にしたところ

## 扱わないコーナーケース
</template>
