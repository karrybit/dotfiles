# 調べてから解説する

- この skill は、調べる部品と解説する部品を順につなぎ、部品の間の受け渡しの条件だけを持つ。調べ方は調べる部品に、解説の作り方は解説する部品に任せる。
- 呼び出し側は次の 3 つを渡す。渡されないものがあれば、始めずに依頼した側に尋ねる。
  - 調べる部品: 話題を調べ、出典つきのノートと、ノートが出典に挙げた原文のファイルを書く skill か subagent と、そのノートを受け入れるかやり直させるかの規則。
  - 入れる手順: ノートと原文のファイルを、ノートのある git のリポジトリの 1 つの commit に入れる手順。
  - 解説する部品: 元の資料の場所と版と読み方と頼まれた内容を受け取って、HTML の解説を作る skill。

## 手順

1. 調べる部品に調べさせ、ノートを受け入れるかやり直させるかを、渡された規則で決める。依頼の目的には、調べたノートが HTML の解説の元の資料になることと、解説の読み手と読んだあとの使い道を書く。受け入れたら、ノートと、報告にある原文の保存先のファイル（原文、原文の一覧、取得の記録）を、入れる手順で 1 つの commit に入れる（解説を作るサブエージェントが、ノートと原文を同じ commit から読むため）。
   完了条件: ノートと原文のファイルを入れた commit が、入れる手順の出力にある。
2. 1 の commit の完全な hash を、`git -C <リポジトリ> rev-parse <1 の commit>` で出す。
   完了条件: commit の完全な hash が手元にある。
3. 解説する部品を呼び、その手順を最後まで進める。元の資料は、git のリポジトリ `<リポジトリ>` の、2 の commit のノートとして渡す。
   - 元の資料の場所は、ノートのリポジトリの中のパス（例: `notes/2026-11-12-<話題>.md`）にする。リポジトリそのものにすると、この skill で作った解説の元の資料がすべて同じになり、前の解説を元の資料で絞れないため。
   - 版は、2 の commit の `git -C <リポジトリ> rev-parse --short <commit>` の出力にする。
   - 読み方には、次の 2 つを書く。ノートと、ノートが出典に挙げた原文を、2 の commit から `git show` で読むこと。ノートは原文を整理した入口なので、概念・関係・仕様・制約の根拠がノートで足りないときと、主張を確かめるときは、ノートの出典の原文の箇所を開いて確かめ、出典には原文の位置を書くこと。
   - 頼まれた内容は、この skill を頼んだ発言の原文にする。

   完了条件: 解説する部品の手順の、最後の完了条件を満たした。
