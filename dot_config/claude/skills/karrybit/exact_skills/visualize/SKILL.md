# 説明の文書を HTML にさせる

- HTML の制作は plugin（`plannotator-effective-html:html`）に任せ、この skill は plugin を活かす仕組み（図法の選び方、design-artifact の design plan、plugin への渡し方、品質のゲート、ブラウザでの確かめ）を依頼の型（[brief.md](brief.md)）に、評価のしかたを下の「依頼の型を直すとき」に持つ。
- 入力は、次の「説明の文書」の形を持つ Markdown 1 ファイル。

## 説明の文書

- `#` の題の直後に、元の資料の場所と版と読み方、読み手と使い道、頼まれた内容の箇条がある。
- 最初の `##` が全体像の節で、対象が何をするかの段落、中心の概念の定義、関係の一覧（「A —動詞→ B（関係の種類。出典）」）、部分をまたぐ動きと、「この文書が答える問い:」で始まる箇条（答えの節へのリンクつき）がある。
- `##` と `###` の見出しが、説明・作業・参照の順のアウトラインになっていて、どの節も見出しの直後に、その節が答える問いの答えの 1 文がある。
- 主張ごとに元の資料の位置（パスと行、ページの節の名前）があり、推論・未確認・未決・食い違いが語の印で示され、食い違いと確かめられなかったことが参照の節の 1 つの `###` に集まっている。
- 入力の文書にこのどれかが欠けるときは、HTML を作らせずに、欠けているものを依頼した側に返す。

## 手順

1. 材料を集める。材料は、説明の文書のパスと、頼まれた内容の原文と、scratchpad のパス。元の資料と読み手は説明の文書の題の直後にある。
   - 置き場所は、依頼に指定がなければ scratchpad の `visualize/<話題>/index.html` にする。説明の文書は、依頼が直してよいと言わなければ「読むだけ」にする。

   完了条件: 型の `<…>` のすべてに入れる値が手元にある。
2. [brief.md](brief.md) の型の `<…>` を埋めて、新しいサブエージェントに Agent tool で頼む。型の `<rubric.md の絶対パス>` は `${CLAUDE_SKILL_DIR}/rubric.md` にする。
   完了条件: サブエージェントの報告に、`index.html` のパスと、`plannotator-effective-html:html` を呼んだことと、説明の文書の誤りと欠けの一覧（なければ「なし」）がある。
3. `index.html` のパスと、説明の文書の誤りと欠けを依頼した側に返す。
   完了条件: 返事に `index.html` の絶対パスがある。

## 依頼の型を直すとき

- 対象は、この skill の [brief.md](brief.md) と、評価の基準の [rubric.md](rubric.md)。決まりごとの出典は [sources.md](sources.md) で読む。sources.md は依頼に入れない。
- rubric.md は、評価するサブエージェントだけに渡し、作るサブエージェントには渡さない。
- 直す欠陥か仮説を決め、元の資料・生成物・生成役のログから原因の手順（型か rubric のどこか）を切り分けてから、その手順の指示を置き換えで最小限に直す。
- 確かめの手順（型の手順 3）の確かめ方か適用の条件だけを直したときは、既存の生成物にその確かめだけをさせて、欠陥を見つけるかで確かめる。これは確かめ方の効き目を示すだけで、新しい生成物が良くなったことは示さない。
- 作る手順（型の手順 1〜2）を直したときは、直した手順とその下流を作り直す（直した手順の出力と下流の作業メモを固定して比べない）。性質の違う説明の文書 2 つと、直すのに使っていない説明の文書 1 つを題材に選ぶ（この skill で前に作った成果物があれば、その入力の説明の文書から選ぶ）。題材ごとに、新しいサブエージェントに直した型で作らせ、別の新しいサブエージェントに rubric.md で評価させて、直す前の型で作った HTML（なければ直す前の型でも作らせる）の評価と並べる。
- 評価させるサブエージェントにも、描画の確認には [brief.md](brief.md) の型の「制約」の chrome-devtools-mcp を使わせる。比べるときは、図の見た目の違いでなく、伝える事実と関係の違い（欠け・誤り）を数える。
- 評価させるサブエージェントには、評価のレポートを最後のメッセージの本文で返させ、ファイルに書かせない。
- 作り手のモデルが替わったときは、局所の確かめで済ませず、作る手順を直したときと同じ 3 つの題材を新しいモデルで作り直して評価させ、前のモデルで作った HTML（なければ前のモデルでも作らせる）の評価と並べる。
