# HTML の見せ方の評価の基準

`brief.md` の依頼の型を直すときに、直した型で作った HTML を評価するサブエージェントに渡す。作るサブエージェントには渡さない。

## 評価のしかた

1. HTML をブラウザで描画して読み、ソースも読む。描画した結果で、console のエラー、見出しの階層、目次とリンクの行き先、必須の操作（折りたたみ・切り替え・検索など）、幅 1280 と 320 での図のラベルの読みやすさ（重なり・切れ・横スクロール）、ネットワークなしでの見た目と機能を確かめ、図の意味と配置は画面写真で見る。視覚設計のゲート（下の「ゲート」の S1〜S6）の材料として、幅 1280 で `h2`・`h3`・答えの文・本文・注釈の文字の大きさと太さ、本文の 1 行の全角の字数と行間、図の文字の描画した大きさ、ページが描くテーマごとの図の文字・確かさの印のコントラストと、図の理解に要る線と形（同じ情報を見える文字で示していないもの。WCAG 2.2 の 1.4.11）のコントラストを測り、幅 320（WCAG 2.2 の 1.4.10）でページの本体の横のあふれを、幅 640（1280 の 200% の拡大、1.4.4）で文字の欠けを確かめ、幅 640 で幅 1280 のときより小さくなる文字が幅 320 で幅 1280 のときの半分以上あるか（どこかの拡大で 200% に届くか）を確かめる。見た目で見出し・表・リストに見えるものが、その意味の要素か ARIA の役割を持つかをソースで確かめる（1.3.1）。ページが描くテーマごとに chrome-devtools-mcp の `lighthouse_audit` の accessibility を走らせ、失敗した監査を控える。Tab で目次・リンク・操作・横にスクロールする容れ物を順に辿り、フォーカスが見えるか、固定した要素に隠れないかを確かめる。1.4.12 は、`evaluate_script` で行の高さ 1.5 倍・字の間隔 0.12em・語の間隔 0.16em・段落の後 2em の `<style>` を足し（日本語の段落の後と語の間隔は言語の例外で省いてよい）、幅 1280 と 320 で文字の切れ・重なり・失われる内容がないかを確かめる（W3C の試験の手順 F104）。2.5.8 は、文の中のリンクを除く操作の要素（ボタン、目次のリンク、summary）の大きさが 24×24 CSS px 以上か、24 px の円が隣の操作の要素に重ならない間隔があるかを測る。1.4.11 は、3:1 に満たない部分を見えないものとみなしても図の理解に要る情報が読めるかで判断する。出典の材料として、開いた直後のページで、出典の一覧（閉じた折りたたみなど）の外に見える文字のうち元の資料のパスと行の文字数と、見える本文の文字数を `evaluate_script` で数え、本文の出典の印（番号か、パスと行）を 3 つ選んで、元の資料の位置が見えるまでの操作の数と、閉じた一覧がそのとき開くかを確かめる。
   完了条件: 描画の確認の項目ごとの結果（測った値か、確かめられなかった理由）がある。
2. HTML の中の事実の主張を、次の決まった選び方で選んで、説明の文書と元の資料と突き合わせる: 冒頭の要約のすべての文、最上位の各節の見出しの直後の 1 文、各表の最初の行のセル、大事な図（下の「ゲート」の G1）のすべての線とラベル。図の中では、描いた部分（SVG か、箱と線を組んだ要素）の線 1 本（両端と線のラベルを合わせて）と、線でない箱・枠・セル・注 1 つを、それぞれ 1 つの主張にし、描いた部分の外の文（`figure` の中の `figcaption`・持ち帰りの 1 文・凡例・`details` の中の文を含む）は図の主張に数えない。ページ自身の構成か書き方を述べる文（節の案内、表記の決めごと）は主張に数えない。資料にない主張は、説明の文書に同じ文か同じ主張があれば「受け継ぎ」、なければ「足した」に分ける。説明の文書が推論・未確認・未決の印を付けた主張を HTML が印なしで書いたものは、「足した」に分ける。
   完了条件: 主張ごとに、元の資料のパスと行、一致・食い違い・資料にない（推論の印の有無）があり、資料にない主張には、出どころと、受け継ぎなら説明の文書の行がある。
3. 下の観点ごとに 1〜5 の点を付け、点の根拠になった箇所（節と要素と引用）を書く。観点 1 と 3 の点は、図の数と図法の種類の多さで上げず、箱と矢印が助けるタスクに合う図を箱と矢印にしたことで下げない。観点 3 は、操作（切り替え・段を進める図など）がないことで下げない。観点 4 は、説明の文書にない文（図の持ち帰りの 1 文、図の注、要約）と、出典の見せ方を見る。観点 4 の減点は、問題ごとに、原文の引用、問題の型（文体の混ざり、直訳、比喩、図との繰り返し、同じ要約の重複、文の流れを切る出典など）、読み手がどう誤読するか迷うかの 1 文がそろった問題だけを根拠にする。
   完了条件: 観点のすべてに、点と根拠の箇所と、直す方向の 1 文がある。
4. 問題を重大・中・軽に分けて挙げる。重大は、読み手が誤った理解のまま作業するか、中心の概念か大事な問いに HTML で辿り着けないもの。
   完了条件: 問題ごとに、重さ、箇所、元の資料の根拠、読み手が困る場面の 1 文がある。

- 1 つの評価役には HTML を 1 つだけ渡す（2 つを並べて読むと、質が近いときに位置の偏りが出る）。比べるときは、HTML ごとの点とゲートと照合の結果を、依頼した側が並べる。
- 点の付け方に迷った箇所は、迷った理由とともに書く。

## 観点

| # | 観点 | 5 の状態 | 1 の状態 |
| --- | --- | --- | --- |
| 1 | 図の適切さと効き目 | どの図も、助けるタスクと持ち帰りの 1 文（読み手が図から持ち帰る結論）が分かり、タスクの性質（構成・やりとり・流れ・状態・比較）に合う形で、図を見ると持ち帰りの 1 文が文より早く分かる。意味の違う関係（包含・順序・対比・依存など）が違う見た目（囲み・位置・並べ方・線）で描き分けられ、見た目が資料にない意味（量、共通部分、因果）を持たない。線と記号の意味が分かる | 図の形がタスクに合わないか、図から何を持ち帰るのかが分からないか、図を読むのに文より手間がかかるか、意味の分からない線や記号がある。意味の違う関係が同じ見た目で描かれて区別できないか、見た目が資料にない意味を示す |
| 2 | HTML の見た目の質 | S1〜S6 がすべて合格で、見た目の調子・色・書体が読み手と対象に合い、色・囲み・印のどれもが意味を持つ。見た目の強さとまとまりが構成の階層と読む順に合い、図・ラベル・凡例が読め、幅 320 でも崩れない。1 ファイルで外のリソースを読み込まない | 文字や図が重なるか切れる、S1〜S6 の 2 つ以上が不合格、外のリソースを読み込む、秘密の値がある |
| 3 | 視覚化の適切さ | 説明の文書の関係・流れ・状態・比較のうち、図か表にすると文より早く分かるものが図か表になり、図の隣で同じ関係を文や箇条で言い直さない。どの図も持ち帰る結論が 1 つに絞られて過密でなく、同じ意味をもっと簡単な表か文で伝えられる図がない。操作があるときは、操作しなくても既定の表示で答えが読め、操作が静的な図より理解を早める | 関係・流れ・状態が箇条や文の並びのまま残り、読み手が頭の中で組み立てる。過密な図か、表か文で済む内容を描いた図か、隣の箇条で同じ関係を繰り返す図がある。操作しないと答えが読めない |
| 4 | 文章と出典の見せ方 | 説明の文書にない文が、説明の文書と同じ文体で、主語・述語・条件が一読で決まり、直訳・比喩・抽象語がない。図の隣の文は図にない条件と例外を書き、同じ要約を 2 か所に書かない。出典は文末の小さな印で本文の流れを切らず、開いた直後のページで本文に元の資料のパスと行が出ず、印から 1 回の操作で主張ごとの位置が見える | 本文の文ごとに元の資料のパスと行が並んで読む流れを切るか、説明の文書にない文が文体の混ざり・直訳・比喩のために中身を推測させ、図の隣の文や要約が同じことを繰り返す |

## ゲート

- 3 と 4 を終えたら、ゲートごとに「合格」「不合格」「未検証」を付け、根拠の箇所か、確かめられなかった理由を書く。
- 表の不合格の条件に 1 つでも当たれば不合格にする。確かめられなかったゲートは未検証にし、合格にしない。材料に 1 があるゲートは、1 の描画をしたときだけ合格にし、描画できなかったときは、ソースで不合格の条件に当たれば不合格、当たらなければ未検証にする。
- 好みに近い小さな問題（軽）は、点に反映し、不合格の理由にしない。

| ゲート | 不合格の条件 | 材料 |
| --- | --- | --- |
| G1 図解の意味 | 大事な図（`figure` 要素のうち、全体像の節とその下の見出しの節にあるものと、HTML の「この文書が答える問い」の箇条の各リンクの行き先の見出しから次の見出し（`figure` の中の見出しを除く）までにあるもの）に意味の誤り（向き・包含・順序の誤り、資料にない意味を持つ見た目）がある | 観点 1 |
| G2 動作 | 主要な図・表・リンク・操作が働かないか、console にページの機能を止めるエラーがある。`file://` で開いて主要な機能が使えない | 1 |
| S1 視覚的階層 | 見た目の強さが構成の階層の順に並ばない（`h3` が本文と同じに見える、見出しより強く見える本文の要素がある）。装飾のために重要度を取り違える箇所がある | 1、観点 2 |
| S2 文字と可読性 | 日本語の本文の 1 行が長すぎるか行間が詰まって読みにくい（目安は全角 40 字前後まで、W3C JLReq 2.4.2）。図の文字かコードが、描画した大きさで注釈の文字より小さい。幅 640 で文字が欠けるか、200% に届かない文字がある | 1 |
| S3 レイアウトとまとまり | 無関係な情報が 1 つのまとまりに見えるか、関連する情報が離れて読み手が取り違える。並列の比較か包含が配置で伝わらない。幅 320 でページの本体が横にあふれる | 1、画面写真 |
| S4 図と文章 | 図の持ち帰りの 1 文か凡例が図の直前か直後になく、読み手が探し回る。図と近くの文が対応しないか、同じ内容を繰り返すだけになっている | 1、観点 1 |
| S5 認知負荷 | 強調が多くて重要度が分からない。問いに効かない装飾か情報が全体像を埋もれさせる。答えに要らない操作かページ内の往復を強いる | 1 |
| S6 一貫性とアクセシビリティ | 同じ役割の部品（確かさの印・目次・出典・凡例）がページの中で違う形になるか、確かさの印が色だけで区別される。ページが描くどれかのテーマで、lighthouse の accessibility に失敗した監査があるか、図の文字・確かさの印のコントラストが 4.5:1 未満か、図の理解に要る線と形が 3:1 未満。複雑な図の関係を文か表で読めない。見た目で見出し・表・リストに見えるものが、その意味の要素か ARIA の役割を持たない。目次・リンク・操作・横にスクロールする容れ物がキーボードで使えないか、フォーカスが見えないか固定した要素に隠れる | 1 |
| S7 出典の追跡 | 2 の主張に、出典の印も元の資料の位置もないものがある。出典の印に、行き先の位置がない。印から位置に 1 回の操作で着けない（閉じた一覧が開かないなど） | 1、2 |

## 報告

- 1 の描画の確認の項目ごとの結果（出典の材料の数を含む）。
- 2 の主張の一覧と照合の結果。
- 資料にない主張の数と、そのうち印のないものの数を、出どころ（受け継ぎ・足した）の行に分けた表。
- 観点ごとの点・根拠の箇所・直す方向（表）。
- 重大・中・軽の問題の一覧。
- ゲートごとの判定と、根拠の箇所か確かめられなかった理由（表）。
- WCAG 2.2 の達成基準（1.1.1、1.3.1、1.4.1、1.4.3、1.4.4、1.4.10、1.4.11、1.4.12、2.1.1、2.4.7、2.4.11、2.5.8、4.1.2 と、lighthouse の失敗が指す基準）ごとの、対象外・合格・不合格・未検証と根拠（表）。lighthouse に通っただけの基準は合格にせず、手で確かめた基準だけを合格にする。
