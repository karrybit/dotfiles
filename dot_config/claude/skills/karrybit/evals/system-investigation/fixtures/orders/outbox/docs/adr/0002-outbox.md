# ADR-0002: 注文のイベントを outbox を通して送る

- 状態: 採用
- 日付: 2026-03-10

## 文脈

注文の API は、注文を DB に保存したあとで確定メールを送っていた。2026-03-04 にメールの API が 40 分止まり、その間の注文 214 件は保存されたのに、確定メールが送られず、再送の手段もなかった。注文の保存と、そのあとの処理の開始を、1 つの transaction で確定させる必要がある。

## 決定

- 注文の行と `order.created` のイベントの行（`outbox`）を、同じ transaction で書く。
- relay が `outbox` の未送信の行を queue に送り、worker が queue から受けて確定メールを送る。
- 注文の API は 202 と `pending` を返し、確定は worker が行う。

## 結果

- メールの API や queue が止まっても、イベントは `outbox` に残り、復旧後に送られる。
- relay は同じ行を 2 回送ることがあるので、worker は `event_id` で重複を捨てる。
- 確定メールは、注文から relay の間隔ぶん遅れる。
