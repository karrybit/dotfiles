# 出題役の依頼の型

`README.md` の「Running」の 1 で、下の型の `<…>` を埋めて、新しいサブエージェントに Agent tool で頼む。

<template>
# <題材の名前> の理解度の問いと正答を作る

## 目的
解説（HTML か Markdown）の読み手が、解説だけを読んで、使い道に要ることを正しく理解できたかを測る問いと正答を、元の資料だけから作る。

## 入力
- 元の資料: <元の資料の場所と版と、読む範囲>
- 読み手と使い道: <読み手と、読んだあとに何に使うか>
- 書き出す先: `<出題のフォルダの絶対パス>` の `questions.md` と `key.md`

## 手順
1. 元の資料を読み、読み手が使い道のために理解する必要のあること（部品と責務、流れと分岐、状態の移り変わり、比べる 2 つの違い、失敗のときに止まる位置と残るもの）を、元の資料のパスと行つきで挙げる。
   完了条件: 挙げたものごとに、元の資料のパスと行か節の名前がある。
2. 1 から問いを 6〜8 個選んで作る。問いの種類は、全体の構成・責務・分岐・比較・遷移と順序・失敗から題材に合うものを選び、4 種類以上を混ぜる。
   - 1 つの問いには、1〜3 文で答えられる 1 つの理解だけを問う。
   - 値を 1 つ引くだけの問い（既定値・期限・名前）は 2 個までにする。
   - 資料どうしか資料と実物が食い違う事柄を問うときは、食い違っていること自体を正答に入れる。
   完了条件: 問いが 6〜8 個あり、種類が 4 つ以上ある。
3. 問いごとに、正答の要点、根拠、取り違えやすい答えを書き、下の形で 2 つのファイルに書き出す。
   - 正答の要点は、照合役が 1 つずつ当否を決められる短い文にし、1 つの問いに 1〜4 個にする。
   - 根拠は、要点ごとに元の資料のパスと行（ページなら節の名前）で書く。
   完了条件: `questions.md` と `key.md` に同じ id の問いが同じ順で並び、`key.md` のどの要点にも根拠がある。

## 形
`questions.md`（読み手に渡す。問いだけを書く）:
```
## Q1
<問い>
```
`key.md`（照合役に渡す）:
```
## Q1
- 問い: <問い>
- 種類: <全体の構成・責務・分岐・比較・遷移と順序・失敗のどれか>
- 正答の要点:
  - <要点>（<根拠>）
- 取り違えやすい答え: <答え>
```

## 制約
- 開くのは元の資料だけにする。この題材の解説（HTML と Markdown）、その作業メモ、`<解説の置き場所>` の下は開かない（問いが解説の書き方に寄るため）。
- 書いてよいのは書き出す先だけ。checkout・fetch・元の資料への書き込みをしない。

## 報告
- `questions.md` と `key.md` の絶対パス。
- 問いごとの id・種類・問いの 1 行。
</template>
