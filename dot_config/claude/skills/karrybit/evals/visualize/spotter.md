# 図解の機会の一覧の型

`README.md` の「Running」の 1 で、下の型の `<…>` を埋めて、新しいサブエージェントに Agent tool で頼む。

<template>
# <題材の名前> の図解の機会の一覧を作る

## 目的
解説（HTML）の評価役が、図解すべき箇所に図があるかを版どうしで同じ物差しで判断できるように、図解の機会の一覧を、元の資料だけから作る。

## 入力
- 元の資料: <元の資料の場所と版と、読む範囲>
- 読み手と使い道: <読み手と、読んだあとに何に使うか>
- 書き出す先: `<出題のフォルダの絶対パス>/opportunities.md`

## 手順
1. 元の資料を、資料全体、節、段落、離れた節どうしの 4 つの粒度で読み、読み手が文から頭の中で組み立てる関係（構成と包含、責務と境界、依存、順序と分岐、時間と期間、条件ごとの結果、比較、節をまたぐ因果）を挙げる。段落の粒度では、どの段落も 1 つずつ読み、2 つ以上の概念か条件をつなぎの語（ので・なら・まで・の後・残る・消える・境界）で結ぶ文と、別の節を指して例外や失敗の経路をつなぐ文を拾う。
   完了条件: 挙げたものごとに、元の資料のパスと行か節の名前がある。
2. 1 から、図を文と併せると、読み手が関係を同時に見る・追う・比べる・境界を見分けることが文だけのときより楽になるものを、図 1 つの持ち帰りの 1 文になる単位で機会として選び、重要度を付ける。使い道に要る問いの答えか中心の概念の関係に要るもの、取り違えると読み手が誤った作業をするものは「高」、ほかは「低」にする。図が文にない手がかりを足さないもの（関係が 1 本だけ、順序も包含もない並列の項目、値の一覧、条件の組み合わせを引く決定表）は選ばない。
   完了条件: どの機会にも重要度があり、「高」の機会が 3〜10 個ある。
3. 下の形で書き出す。
   完了条件: `opportunities.md` のどの機会にも、根拠と、図で分からせることと、重要度がある。

## 形
```
## O1
- 箇所: <元の資料のパスと行か節の名前>
- 図で分からせること: <読み手が図から持ち帰る 1 文>
- 出す概念と関係: <概念と、その間の関係>
- 重要度: <高か低>
```

## 制約
- 開くのは元の資料だけにする。この題材の解説（HTML と Markdown）、その作業メモ、`<解説の置き場所>` の下は開かない（一覧が解説の図に寄るため）。
- 書いてよいのは書き出す先だけ。checkout・fetch・元の資料への書き込みをしない。

## 報告
- `opportunities.md` の絶対パス。
- 機会ごとの id・重要度・図で分からせることの 1 行。
</template>
